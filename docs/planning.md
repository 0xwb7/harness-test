# Planning Guidelines

## 1. 계획 수립 기준

다음과 같은 작업을 수행하는 경우 문서화된 실행 계획을 수립한다.

- 여러 컴포넌트를 변경해야 하는 작업
- 아키텍처에 중요한 변경사항이 발생하는 작업
- 동시성 문제나 복잡한 상태 전환을 다루는 작업
- 데이터베이스의 여러 변경사항을 함께 조정해야 하는 작업
- 기술적으로 불확실성이 크거나 사전 검토가 필요한 작업

단순한 코드 수정이나 작은 규모의 작업에는 별도의 실행 계획을 작성하지 않는다.

## 2. 계획서 구성

실행 계획에는 다음 내용을 포함한다.

### 목표(Goal)

- 작업을 통해 달성해야 하는 목표를 명확하게 정의한다.

### 작업 범위(Scope)

- 변경하거나 구현해야 하는 기능과 컴포넌트를 정의한다.

### 제약사항(Constraints)

- 작업 과정에서 반드시 준수해야 하는 요구사항과 규칙을 정리한다.
- 기존 동작 중 유지해야 하는 사항을 명확하게 한다.

### 구현 단계(Implementation Steps)

- 목표를 달성하기 위해 필요한 주요 구현 단계를 정리한다.
- 각 단계에서 수행해야 할 작업을 명확하게 작성한다.

### 검증 방법(Verification)

- 구현 결과가 요구사항을 충족하는지 확인할 방법을 정의한다.
- 필요한 테스트와 검증 절차를 정리한다.

### 위험 요소(Risks)

- 작업 과정에서 발생할 수 있는 문제와 실패 가능성을 식별한다.

## 3. 계획 실행

- 실행 계획은 불필요하게 길어지지 않도록 간결하게 작성한다.
- 작업을 작은 단위로 나누어 진행하고, 각 단계에서 결과를 검증한다.
- 기존 가정이나 작업 조건이 변경되면 실행 계획을 수정한다.
- 명확한 이유 없이 작업 범위를 확장하지 않는다.
- 필요한 경우 중요한 기술적 결정과 그 이유를 기록한다.

## 4. 작업 완료

복잡한 작업을 완료하기 전에 다음 사항을 확인하라

- 계획한 구현 단계가 모두 수행되었는지 확인
- 정의된 인수 조건(Acceptance Criteria)을 충족하는지 검증
- 해결되지 않은 문제나 제약사항을 기록
- 최종 구현 결과가 최초 요구사항과 일치하는지 확인
